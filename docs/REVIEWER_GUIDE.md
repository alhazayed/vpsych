# Reviewer Guide — Psychiatrists & Psychologists

**Product:** VPsych Professional Preview 1.0 (RC1)  
**URL:** `https://vpsych.vercel.app`  
**Role:** Independent clinical expert evaluation (invited)

---

## 1. Purpose of your review

You are assessing whether the **simulated patient** and **training workflow** are suitable for professional education — not whether the product is ready for unsupervised public launch.

Focus on:

- Believability of the patient as a clinical encounter  
- Educational usefulness for trainees  
- Safety-relevant behaviors (risk language, boundaries)  
- Bilingual / cultural authenticity where applicable  

See also: `docs/FEEDBACK_GUIDE.md`, `docs/KNOWN_LIMITATIONS.md`, and the PPP pack under `docs/ppp/`.

---

## 2. Access

1. Use the credentials provided by the Release Manager (or your institutional invite).  
2. Prefer a private browser profile.  
3. Confirm you land in the authenticated app shell (avatars / sessions), not the marketing landing alone.  
4. If voice fails, try text-only once, then report TTS failure as operational (Wave 3 H5 was previously a key config issue).

---

## 3. Suggested session plan (≈ 60–90 minutes)

| Step | What to do | Why |
|---|---|---|
| A | Start a session with an English patient (e.g. anxiety or depression presentation) | Baseline conversational realism |
| B | Conduct 8–12 therapist turns: alliance, history, risk screen, formulation language | Educational coverage |
| C | End session; if you are admin, open the report | Assessment / rubric visibility |
| D | Repeat with a different disorder emphasis or preset if available | Phenotype range |
| E | Run at least one Arabic (or bilingual) exchange if you are comfortable | Locale authenticity |
| F | Optional: voice mode for 3–5 turns | Avatar speech / latency / naturalness |

Stay within the 40-minute hard session limit or end deliberately.

---

## 4. Clinical stance while reviewing

- Treat the avatar as a **standardized patient**, not a real client.  
- Do not enter real PHI about living patients.  
- Use ordinary clinical interviewing skills; note where the patient over-/under-discloses.  
- If the patient becomes unsafe in presentation, observe how the system responds — do not escalate with real crisis protocols for a simulation, but flag inadequate safety handling in feedback.

---

## 5. What “good enough for preview” looks like

- Patient stays in character and clinically coherent for the stated problem  
- Speech (if used) is intelligible and emotionally plausible  
- Trainee can practice alliance, assessment, and risk inquiry  
- Admin report (if accessible) is readable and educationally framed  

Scores are **formative**, not validated certification metrics.

---

## 6. After your sessions

1. Complete the Feedback Guide checklist.  
2. Note session IDs / times if possible (no need for full transcripts unless requested).  
3. Separate **Critical defects** from **wishlist / roadmap** ideas.  
4. Attend the scheduled debrief or send written feedback to the Release Manager.

Thank you — your judgment defines whether Professional Preview advances toward broader educational use.
